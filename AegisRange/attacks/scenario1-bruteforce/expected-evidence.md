# Scenario 1 — Expected Evidence

> This document describes the exact evidence generated by the SSH credential testing
> scenario and where to find it. Use this as a reference when building collectors,
> detection rules, and correlation logic.

## Evidence Summary

| # | Evidence Type | Source System | Log File / Location | Event Count (approx) |
|---|---|---|---|---|
| 1 | Failed SSH authentication | aegis-linux | `/var/log/auth.log` | ~26 entries |
| 2 | Successful SSH authentication | aegis-linux | `/var/log/auth.log` | 1 entry |
| 3 | Session opened/closed | aegis-linux | `/var/log/auth.log` | 2 entries |
| 4 | Command execution (execve) | aegis-linux | `/var/log/audit/audit.log` | ~10 entries |
| 5 | Sensitive file read | aegis-linux | `/var/log/audit/audit.log` | 1 entry |
| 6 | Network connections | aegis-linux | ss / netstat output | Ongoing |

## 1. Failed SSH Authentication

**Source**: `/var/log/auth.log`
**Pattern**: Burst of "Failed password" entries from `10.10.10.10` within a short time window

### Example Log Lines
```
Oct 21 14:23:01 aegis-linux sshd[4521]: Failed password for labuser from 10.10.10.10 port 45678 ssh2
Oct 21 14:23:01 aegis-linux sshd[4523]: Failed password for labuser from 10.10.10.10 port 45680 ssh2
Oct 21 14:23:02 aegis-linux sshd[4525]: Failed password for labuser from 10.10.10.10 port 45682 ssh2
Oct 21 14:23:02 aegis-linux sshd[4527]: Failed password for labuser from 10.10.10.10 port 45684 ssh2
... (approximately 26 failed attempts)
```

### Key Fields to Parse
| Field | Value | Notes |
|---|---|---|
| Timestamp | `Oct 21 14:23:01` | Syslog format |
| Hostname | `aegis-linux` | Source system |
| Service | `sshd` | SSH daemon |
| PID | `4521` | Process ID |
| Event | `Failed password` | Authentication failure |
| Username | `labuser` | Target account |
| Source IP | `10.10.10.10` | Attacker (Kali) |
| Source Port | `45678` | Ephemeral port |
| Protocol | `ssh2` | SSH version 2 |

### Detection Pattern
- **Threshold**: More than 5 "Failed password" entries from the same source IP within 60 seconds
- **Regex**: `Failed password for (\S+) from (\S+) port (\d+)`

---

## 2. Successful SSH Authentication

**Source**: `/var/log/auth.log`
**Pattern**: "Accepted password" entry from `10.10.10.10` — typically appears right after the burst of failures

### Example Log Lines
```
Oct 21 14:23:15 aegis-linux sshd[4553]: Accepted password for labuser from 10.10.10.10 port 45702 ssh2
Oct 21 14:23:15 aegis-linux sshd[4553]: pam_unix(sshd:session): session opened for user labuser(uid=1001) by (uid=0)
```

### Detection Pattern
- **Correlation**: Successful auth from an IP that had >5 failures in the preceding 5 minutes
- **Regex**: `Accepted password for (\S+) from (\S+) port (\d+)`

## 4. Command Execution (auditd)

**Source**: `/var/log/audit/audit.log`
**Pattern**: `execve` syscall records for commands run by `labuser` after login

### Example Log Lines
```
type=SYSCALL msg=audit(1634825000.123:456): arch=c000003e syscall=59 success=yes exit=0 a0=... a1=... a2=... a3=... items=2 ppid=4553 pid=4560 auid=1001 uid=1001 gid=1001 euid=1001 ... comm="whoami" exe="/usr/bin/whoami" key="command_execution"
type=EXECVE msg=audit(1634825000.123:456): argc=1 a0="whoami"

type=SYSCALL msg=audit(1634825002.456:457): ... comm="cat" exe="/usr/bin/cat" key="command_execution"
type=EXECVE msg=audit(1634825002.456:457): argc=2 a0="cat" a1="/etc/passwd"
```

### Commands That Generate Evidence
| Command | Purpose | Suspicious? |
|---|---|---|
| `whoami` | Identity check | Low — common post-login |
| `id` | Group enumeration | Low |
| `uname -a` | System info | Low |
| `cat /etc/passwd` | User enumeration | **Medium** — info gathering |
| `ip addr` | Network enumeration | Low |
| `ss -tlnp` | Service enumeration | **Medium** — recon activity |
| `ps aux` | Process enumeration | Low |

## 5. Network Evidence

**Source**: Network layer / collector captures

### Evidence
- Multiple TCP connections from `10.10.10.10` to `10.10.10.20:22` in rapid succession
- Each failed Hydra attempt creates a new TCP connection
- Pattern: SYN → SYN-ACK → ACK → SSH handshake → AUTH → FAIL → FIN

---

## Timeline Pattern

The attack produces a distinctive timeline pattern:

```
T+0s    : Nmap SYN scan (ports 22, 21, 80)
T+2s    : Nmap service version probes
T+5s    : First Hydra SSH attempt (password: "password") — FAIL
T+5.1s  : Second attempt (password: "123456") — FAIL
...     : (rapid succession of failures, ~4 per second)
T+11s   : Attempt #27 (password: "labpass123") — SUCCESS
T+13s   : SSH session opened for labuser
T+14s   : Post-login commands begin (whoami, id, etc.)
T+20s   : Sensitive file access (cat /etc/passwd)
T+30s   : SSH session closed
```

This pattern — **scan → rapid auth failures → success → enumeration** — is the key signature for correlation.
